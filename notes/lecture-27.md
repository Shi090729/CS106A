# Lecture 27 - Computer Science Beyond Programming

## Course Content

### Computer science is broader than programming

Near the end of the course, the lecture steps back from individual Java features and asks what computer science studies. Programming is one way to express an idea, but the field also includes algorithms, systems, architecture, theory, artificial intelligence, graphics, robotics, human-computer interaction, and data analysis. The same small program can therefore be studied from several perspectives: what it computes, how much time and memory it uses, and how a person experiences it.

### Recursion and other next-step ideas

The lecture introduces recursion as an example of a later idea that changes how a programmer thinks about methods. A method can call itself when the problem contains a smaller version of the same structure, but the design must include a base case and a step that moves toward it. Recursion is not presented as another syntax trick; it is a way to describe a problem whose definition naturally refers to itself.

`CS106B` continues programming with recursion and more advanced data structures. `CS103` develops discrete mathematics, logic, sets, computability, and complexity questions such as P versus NP. These courses illustrate two different ways to continue: expanding the programs one can build and expanding the mathematical tools used to reason about computation.

### Tradeoffs and constraints

There is no best representation without a goal. Saving memory may cost time, a faster lookup structure may require extra bookkeeping, and a more abstract design may be worthwhile because it is easier to change. The course's small examples provide a place to practice stating the constraint first and then deciding which cost matters most.

### Choosing a direction after CS106A

The lecture closes by describing possible paths after the course rather than prescribing one. A student interested in efficiency might continue with algorithms and theory; someone interested in intelligent behavior might explore artificial intelligence or robotics; someone interested in people and interfaces might study HCI. Documentation, experiments, and reading existing code remain normal tools in all of those areas.

Computer science can be pursued as a major, minor, or supporting skill inside another field. The important decision is not whether every student becomes a software engineer, but which computational ideas are useful for the questions that student wants to study.

## My Takeaways

I appreciated the reminder that becoming a better programmer is not the same as memorizing more APIs. The transferable skill is being able to ask a precise question, build a small experiment, and use the result to revise my model.

The discussion of recursion also showed me that later computer science courses will change the kinds of descriptions I can use, not just give me larger libraries. CS106A is a foundation, not a boundary.
